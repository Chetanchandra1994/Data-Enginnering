terraform/

Azure DevOps sees the push and starts the pipeline.

The pipeline asks:

Python

Does the Python code work?

dbt

Is the dbt project valid?
Do dependencies compile?
Do tests pass?

Terraform

Is the Terraform syntax valid?
Is the configuration structurally valid?
What infrastructure would change?

If something fails:

Git
 ↓
Azure Pipeline
 ↓
❌ FAIL

The code should not be promoted.

If everything passes:

Git
 ↓
Azure Pipeline
 ↓
✅ PASS
 ↓
Eligible for deployment

That's CI.

One important architectural distinction

We'll keep ownership clean:

Component	Managed by
Snowflake DB/Warehouse/Schemas/Stages/etc.	Terraform
Transformation SQL	dbt
Python ingestion code	Git + CI/CD
Airflow DAGs	Git + CI/CD
Pipeline definition	Azure DevOps
Secrets	Azure secure mechanisms
Data	Snowflake/GCS

This prevents us from creating a messy project where Terraform, dbt and Azure Pipelines all try to manage the same objects.
