🚀 Snowpipe

Now we'll connect the Pub/Sub event to Snowflake Snowpipe so that:

GCS
   ↓
Pub/Sub
   ↓
Snowpipe AUTO_INGEST
   ↓
Snowflake LANDING

Before creating the Snowpipe objects, we'll set up the Snowflake side in the correct order:

GCS Storage Integration
GCS access for Snowflake
Snowflake Notification Integration
Give Snowflake's generated service account Pub/Sub Subscriber access
External Stage
File Format
LANDING table
Snowpipe with AUTO_INGEST = TRUE
Upload a new test file
Verify the row count in LANDING

This is an important production architecture concept, so we'll do it properly rather than just making the pipe work.

Let's start the Snowflake side.
----------------------------------------------------------------------------------------------------------------------------------------------
----------------------------------------------  CONTINUATION AFTER PUB/SUB STEPS  ------------------------------------------------------------
----------------------------------------------------------------------------------------------------------------------------------------------

----------------------------------------------------------------------------------------------------------------------------------------------
Step 8 — Create the GCS Storage Integration
----------------------------------------------------------------------------------------------------------------------------------------------

We first need Snowflake to have controlled access to:

gs://advworks-dev-ingestion/

This integration will allow Snowflake/Snowpipe to read the JSONL files from GCS without putting GCP service-account keys or passwords into our project.

Open Snowflake → Worksheets and make sure you're using:

Role: ACCOUNTADMIN
Database: ADVWORKS_DEV
Warehouse: ETL_WH_DEV

Run:

CREATE OR REPLACE STORAGE INTEGRATION ADVWORKS_GCS_INT
  TYPE = EXTERNAL_STAGE
  STORAGE_PROVIDER = 'GCS'
  ENABLED = TRUE
  STORAGE_ALLOWED_LOCATIONS = ('gcs://advworks-dev-ingestion/fact_internet_sales/');

output:
Integration ADVWORKS_GCS_INT successfully created.  

This is deliberately restricted to the fact_internet_sales/ path rather than giving Snowflake access to the entire bucket. That's the better production practice. Snowflake supports path-level restrictions through STORAGE_ALLOWED_LOCATIONS.

----------------------------------------------------------------------------------------------------------------------------------------------
Step 9 — Get Snowflake's GCS service account
----------------------------------------------------------------------------------------------------------------------------------------------

Immediately after the CREATE succeeds, run:

DESC INTEGRATION ADVWORKS_GCS_INT;

Look for this property:

STORAGE_GCP_SERVICE_ACCOUNT

It will look approximately like:

something@something.iam.gserviceaccount.com

----------------------------------------------------------------------------------------------------------------------------------------------
Step 10 — Grant Snowflake read access to GCS
----------------------------------------------------------------------------------------------------------------------------------------------

Now we need to allow this Snowflake service account to read objects from our GCS bucket/path.

Run this one-line PowerShell command:

gcloud storage buckets add-iam-policy-binding gs://advworks-dev-ingestion --member="serviceAccount:kerg30000@gcpmecentral2-1-6ca6.iam.gserviceaccount.com" --role="roles/storage.objectViewer" --project=electric-tesla-507710-k2

This gives Snowflake:

Object Viewer → read/download GCS objects

It does not give Snowflake permission to delete or modify your files.

Why we're doing this

Our architecture is becoming:

GCS
 │
 │ Snowflake Storage Integration
 │
 ▼
Snowflake GCS Service Account
 │
 │ read objects
 ▼
Snowpipe
 │
 ▼
ADVWORKS_DEV.LANDING

So the GCS → Snowflake file-access path is ready.

----------------------------------------------------------------------------------------------------------------------------------------------
Step 11 — Create the Snowflake Notification Integration
----------------------------------------------------------------------------------------------------------------------------------------------

Now we connect Snowflake to the Pub/Sub subscription we already created.

In Snowflake, run:

CREATE OR REPLACE NOTIFICATION INTEGRATION ADVWORKS_GCS_PUBSUB_INT
  TYPE = QUEUE
  NOTIFICATION_PROVIDER = GCP_PUBSUB
  ENABLED = TRUE
  GCP_PUBSUB_SUBSCRIPTION_NAME = 'projects/electric-tesla-507710-k2/subscriptions/advworks-dev-gcs-events-sub';

Then run:

DESC NOTIFICATION INTEGRATION ADVWORKS_GCS_PUBSUB_INT;

Look for:

GCP_PUBSUB_SERVICE_ACCOUNT

Snowflake will provide another Google service account.

We now have the Snowflake Pub/Sub service account. Notice the distinction:

GCS Storage Integration             →  reads GCS objects
Snowflake Notification Integration  →  reads Pub/Sub notifications

----------------------------------------------------------------------------------------------------------------------------------------------
Step 12 — Grant Snowflake Pub/Sub Subscriber permission
----------------------------------------------------------------------------------------------------------------------------------------------

Run this one-line PowerShell command:

gcloud pubsub subscriptions add-iam-policy-binding advworks-dev-gcs-events-sub --member="serviceAccount:kfrg30000@gcpmecentral2-1-6ca6.iam.gserviceaccount.com" --role="roles/pubsub.subscriber" --project=electric-tesla-507710-k2

Expected output will contain:

role: roles/pubsub.subscriber
members:
- serviceAccount:kfrg30000@gcpmecentral2-1-6ca6.iam.gserviceaccount.com
