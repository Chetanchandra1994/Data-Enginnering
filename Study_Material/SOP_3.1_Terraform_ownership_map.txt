The 4 identities you should never confuse
Identity	Purpose
Azure DevOps identity	Proves the pipeline is allowed to federate into GCP
terraform-ci@...	Terraform's GCP automation identity
GCS service agent	Publishes GCS events to Pub/Sub
Snowflake notification service account	Reads Pub/Sub notifications for Snowpipe

And there is a separate Snowflake Terraform identity used by Terraform to create/manage Snowflake objects.

Interview shortcut

If asked “Who gives access to whom?”, think:

WHO                         ACCESS TO                 WHY

Azure DevOps
   ↓ WIF
GCP Terraform SA            GCP infrastructure        Terraform provisioning

GCS Service Agent
   ↓ publisher
Pub/Sub Topic               GCS events                Notify file creation

Snowflake Notification SA
   ↓ subscriber
Pub/Sub Subscription        Snowpipe events           Consume notifications

Snowflake Storage Integration
   ↓ GCS access
GCS Bucket                  Read source files         Snowpipe ingestion

Terraform Snowflake User
   ↓ Snowflake role
Snowflake objects           Create/manage infra       IaC provisioning

Most important distinction:
Terraform creates/provisions the infrastructure; IAM grants the identities permission; runtime service accounts perform the actual data movement.

That distinction will be very useful when we turn this project into your interview questions.
