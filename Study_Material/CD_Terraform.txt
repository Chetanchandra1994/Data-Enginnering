One important learning point

This is a very common real-world Terraform issue:
Terraform doesn't determine infrastructure ownership simply by looking at Snowflake. It determines ownership through its state.
That's why production pipelines almost never rely on a developer's local terraform.tfstate.

Terraform state is what maps Terraform resources to real infrastructure.

In a real company, we therefore need:

             Remote Terraform State
                     │
                     ▼
Git → Plan → Review → Apply
                     │
                     ▼
                 Snowflake

Since your architecture already uses GCP/GCS, we'll use a GCS Terraform backend. 
The GCS backend supports remote state and state locking, and HashiCorp recommends bucket versioning for recovery.
