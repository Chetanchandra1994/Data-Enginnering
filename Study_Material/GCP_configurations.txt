Azure DevOps Ubuntu agent needs authentication to GCP so it can access that GCS state bucket.

We will not use personal gcloud auth login credentials in Azure DevOps.

For CI/CD, we'll create a dedicated Google Cloud service account for Terraform state access.

Our architecture will become:

                       ▼
                  Snowflake

Create Terraform CI service account

First, let's enable the IAM API.

Run this one-line PowerShell command:

gcloud services enable iam.googleapis.com

Then create a dedicated service account:

gcloud iam service-accounts create terraform-ci --display-name="Terraform CI/CD Service Account"

Verify it exists:

gcloud iam service-accounts list

You should see something like:

terraform-ci@electric-tesla-507710-k2.iam.gserviceaccount.com

Grant bucket-level permissions

Run this one-line PowerShell command:

gcloud storage buckets add-iam-policy-binding gs://electric-tesla-507710-k2-tfstate --member="serviceAccount:terraform-ci@electric-tesla-507710-k2.iam.gserviceaccount.com" --role="roles/storage.objectAdmin"

This gives the CI service account permission to:

read Terraform state
write Terraform state
update state
delete/replace state objects when Terraform needs to

It does not give the service account broad access to your entire GCP project.

— Verify the permission

Run:

gcloud storage buckets get-iam-policy gs://electric-tesla-507710-k2-tfstate

You should see something containing:

role: roles/storage.objectAdmin
members:
- serviceAccount:terraform-ci@electric-tesla-507710-k2.iam.gserviceaccount.com
