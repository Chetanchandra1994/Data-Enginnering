LANDING is not a dbt model in our design. Snowpipe is responsible for putting the raw data into landing tables.

DBT starts after LANDING i.e LANDING is the primary Source for DBT transformations

Our architecture is:

LANDING (Capture what arrived from the source using Snowpipe)
   │
   │ Raw data from Snowpipe
   ↓
PREPARE (PREPARE is where we start making the data usable for downstream transformations.)
   │
   │ Type/standardize/initial transformation
   ↓
NORMALIZE
   │
   │ Clean/enrich/business preparation
   ↓
SCHEMATIZE
   │
   │ Dimensional model
   ↓
MARKETPLACE
   │
   │ Business-facing consumption
   ↓
BI Reports

Create:

models\schematize\dim_date.sql

with:

{{ config(
    materialized='table',
    schema='SCHEMATIZE'
) }}

WITH date_spine AS (

    SELECT
        DATEADD(
            DAY,
            SEQ4(),
            '2010-01-01'::DATE
        ) AS FULL_DATE

    FROM TABLE(
        GENERATOR(
            ROWCOUNT => 10000
        )
    )

)

SELECT
    TO_NUMBER(TO_CHAR(FULL_DATE, 'YYYYMMDD')) AS DATE_KEY,
    FULL_DATE,

    YEAR(FULL_DATE) AS YEAR,
    QUARTER(FULL_DATE) AS QUARTER,
    MONTH(FULL_DATE) AS MONTH,
    MONTHNAME(FULL_DATE) AS MONTH_NAME,

    WEEKOFYEAR(FULL_DATE) AS WEEK_OF_YEAR,

    DAY(FULL_DATE) AS DAY_OF_MONTH,
    DAYOFWEEK(FULL_DATE) AS DAY_OF_WEEK,
    DAYNAME(FULL_DATE) AS DAY_NAME,

    CASE
        WHEN DAYOFWEEK(FULL_DATE) IN (1, 7)
        THEN TRUE
        ELSE FALSE
    END AS IS_WEEKEND

FROM date_spine

This creates a 10,000-day calendar.

Don't worry that our current sales data only covers part of this range. A reusable date dimension intentionally covers a broader range.
