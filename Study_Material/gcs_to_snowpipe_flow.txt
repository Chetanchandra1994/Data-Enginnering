Below is the full first-time GCS → Pub/Sub → Snowflake Snowpipe → Landing Table implementation, with the creation order, access/IAM order, verification steps, and runtime data path, and code for each step.

In this architecture some resources cannot be created/configured correctly until a previous resource exists.

Important: The examples below use placeholders such as PROJECT_ID, BUCKET_NAME, TOPIC_NAME, etc. They should be replaced with the actual practice-project values. The Snowflake objects follow the architecture we've been building: LANDING, external stage, storage integration, notification integration and Snowpipe.

1. SET VARIABLES

First define the values that will be reused.

GCP
export PROJECT_ID="your-gcp-project-id"
export REGION="us-central1"

export BUCKET_NAME="advworks-dev-raw"
export GCS_PATH="dimcustomer"

export TOPIC_NAME="snowpipe-dimcustomer-topic"
export SUBSCRIPTION_NAME="snowpipe-dimcustomer-subscription"

Set the project:

gcloud config set project $PROJECT_ID

Verify:

gcloud config get-value project
2. ENABLE REQUIRED GCP APIs
gcloud services enable \
  storage.googleapis.com \
  pubsub.googleapis.com

Verify:

gcloud services list --enabled
3. CREATE GCS BUCKET

Create the bucket:

gcloud storage buckets create gs://$BUCKET_NAME \
  --location=$REGION \
  --uniform-bucket-level-access

Verify:

gcloud storage buckets describe gs://$BUCKET_NAME
4. CREATE GCS DIRECTORY/PREFIX

GCS doesn't technically have folders, but we create an object prefix.

echo "placeholder" > placeholder.txt

gcloud storage cp \
  placeholder.txt \
  gs://$BUCKET_NAME/$GCS_PATH/placeholder.txt

Remove placeholder:

gcloud storage rm \
  gs://$BUCKET_NAME/$GCS_PATH/placeholder.txt

Result:

gs://advworks-dev-raw/
        │
        └── dimcustomer/
5. CREATE PUB/SUB TOPIC
gcloud pubsub topics create $TOPIC_NAME

Verify:

gcloud pubsub topics describe $TOPIC_NAME

Result:

GCS
 ↓
Pub/Sub Topic
6. CREATE PUB/SUB SUBSCRIPTION

Create subscription attached to the topic:

gcloud pubsub subscriptions create $SUBSCRIPTION_NAME \
  --topic=$TOPIC_NAME

Verify:

gcloud pubsub subscriptions describe $SUBSCRIPTION_NAME

Architecture now:

GCS
 ↓
TOPIC
 ↓
SUBSCRIPTION
7. GET GCS SERVICE AGENT

GCS uses a Google-managed service agent to publish object notifications.

Get the project number:

export PROJECT_NUMBER=$(gcloud projects describe $PROJECT_ID \
  --format="value(projectNumber)")

GCS service agent:

export GCS_SERVICE_AGENT="service-${PROJECT_NUMBER}@gs-project-accounts.iam.gserviceaccount.com"

Verify:

echo $GCS_SERVICE_AGENT
8. GRANT PUB/SUB PUBLISHER TO GCS SERVICE AGENT

This allows GCS to publish notifications to the topic.

gcloud pubsub topics add-iam-policy-binding $TOPIC_NAME \
  --member="serviceAccount:$GCS_SERVICE_AGENT" \
  --role="roles/pubsub.publisher"

Verify:

gcloud pubsub topics get-iam-policy $TOPIC_NAME

You should see:

roles/pubsub.publisher
    ↓
GCS service agent
9. CREATE GCS → PUB/SUB NOTIFICATION

Now tell GCS:

Whenever an object is created in this bucket, publish an event to this topic.

gcloud storage buckets notifications create \
  gs://$BUCKET_NAME \
  --topic=$TOPIC_NAME \
  --event-types=OBJECT_FINALIZE

Verify:

gcloud storage buckets notifications list \
  gs://$BUCKET_NAME

Now:

GCS Bucket
    │
    │ OBJECT_FINALIZE
    ▼
Pub/Sub Topic
10. CREATE SNOWFLAKE STORAGE INTEGRATION

Now we move into Snowflake.

Connect to Snowflake with an administrative/deployment role.

USE ROLE ACCOUNTADMIN;

Create the storage integration:

CREATE OR REPLACE STORAGE INTEGRATION GCS_ADVWORKS_STORAGE_INT
  TYPE = EXTERNAL_STAGE
  STORAGE_PROVIDER = GCS
  ENABLED = TRUE
  STORAGE_ALLOWED_LOCATIONS = (
      'gcs://advworks-dev-raw/dimcustomer/'
  );

Check it:

DESC INTEGRATION GCS_ADVWORKS_STORAGE_INT;

This is an extremely important command.

Snowflake will return information including the generated:

STORAGE_GCP_SERVICE_ACCOUNT

Save that value.

For example:

<generated-snowflake-service-account>
11. GRANT GCS ACCESS TO SNOWFLAKE STORAGE SERVICE ACCOUNT

The Snowflake service account needs permission to read objects from GCS.

Grant:

gcloud storage buckets add-iam-policy-binding \
  gs://$BUCKET_NAME \
  --member="serviceAccount:<SNOWFLAKE_GCP_SERVICE_ACCOUNT>" \
  --role="roles/storage.objectViewer"

For a narrower design, object-level IAM can be considered, but bucket-level roles/storage.objectViewer is the common straightforward setup.

Verify:

gcloud storage buckets get-iam-policy \
  gs://$BUCKET_NAME

The flow is now:

Snowflake Storage Integration
             ↓

             ↓
GCS IAM
             ↓

For our DimCustomer example:

21. CREATE SNOWPIPE

Now all the dependencies exist:

GCS
 ↓
Topic
 ↓

 ↓
GCS Notification
 ↓

 ↓

 ↓

Now create the pipe.

Example using the raw VARIANT approach:

CREATE OR REPLACE PIPE ADVWORKS_DEV.LANDING.DIMCUSTOMER_PIPE
  AUTO_INGEST = TRUE
  INTEGRATION = 'GCS_ADVWORKS_NOTIFICATION_INT'
AS
COPY INTO ADVWORKS_DEV.LANDING.DIMCUSTOMER_RAW
(
    RAW_DATA,
    SOURCE_FILE_NAME,
    LOAD_TIMESTAMP
)
FROM (
    SELECT
        $1,
        METADATA$FILENAME,
        CURRENT_TIMESTAMP()
    FROM @ADVWORKS_DEV.LANDING.DIMCUSTOMER_STAGE
)
FILE_FORMAT = (
    FORMAT_NAME = ADVWORKS_DEV.LANDING.DIMCUSTOMER_JSON_FORMAT
);

31. TERRAFORM — DEFINE GCS

For the actual infrastructure-as-code implementation:

resource "google_storage_bucket" "raw" {
  name     = var.bucket_name
  location = var.region

  uniform_bucket_level_access = true
}
32. TERRAFORM — DEFINE PUB/SUB TOPIC
resource "google_pubsub_topic" "snowpipe" {
  name = var.topic_name
}
33. TERRAFORM — DEFINE SUBSCRIPTION
resource "google_pubsub_subscription" "snowpipe" {
  name  = var.subscription_name
  topic = google_pubsub_topic.snowpipe.id
}
34. TERRAFORM — GCS SERVICE AGENT → PUB/SUB
resource "google_pubsub_topic_iam_member" "gcs_publisher" {
  topic  = google_pubsub_topic.snowpipe.name
  role   = "roles/pubsub.publisher"
  member = "serviceAccount:service-${data.google_project.current.number}@gs-project-accounts.iam.gserviceaccount.com"
}
35. TERRAFORM — GCS NOTIFICATION

Conceptually:

resource "google_storage_notification" "snowpipe" {
  bucket         = google_storage_bucket.raw.name
  topic          = google_pubsub_topic.snowpipe.id
  payload_format = "JSON_API_V1"

  event_types = [
    "OBJECT_FINALIZE"
  ]
}
36. TERRAFORM — GCS ACCESS FOR SNOWFLAKE
resource "google_storage_bucket_iam_member" "snowflake_reader" {
  bucket = google_storage_bucket.raw.name
  role   = "roles/storage.objectViewer"
  member = "serviceAccount:${var.snowflake_gcp_service_account}"
}
37. TERRAFORM — PUB/SUB ACCESS FOR SNOWFLAKE
resource "google_pubsub_subscription_iam_member" "snowflake_subscriber" {
  subscription = google_pubsub_subscription.snowpipe.name
  role         = "roles/pubsub.subscriber"
  member       = "serviceAccount:${var.snowflake_pubsub_service_account}"
}
38. TERRAFORM — SNOWFLAKE OBJECTS

Your Snowflake Terraform provider configuration would then manage objects such as:

resource "snowflake_storage_integration" "gcs" {
  name    = "GCS_ADVWORKS_STORAGE_INT"
  enabled = true

  type             = "EXTERNAL_STAGE"
  storage_provider = "GCS"

  storage_allowed_locations = [
    "gcs://advworks-dev-raw/dimcustomer/"
  ]
}

External stage:

resource "snowflake_stage" "dimcustomer" {
  name = "DIMCUSTOMER_STAGE"

  database = "ADVWORKS_DEV"
  schema   = "LANDING"

  url = "gcs://advworks-dev-raw/dimcustomer/"

  storage_integration = "GCS_ADVWORKS_STORAGE_INT"
}

Notification integration:

resource "snowflake_notification_integration" "gcs" {
  name    = "GCS_ADVWORKS_NOTIFICATION_INT"
  enabled = true

  type                  = "QUEUE"
  notification_provider = "GCP_PUBSUB"

  gcp_pubsub_subscription_name = var.pubsub_subscription_full_name
}

The exact Terraform resource arguments should be aligned with the Snowflake provider version because provider schemas can differ.
